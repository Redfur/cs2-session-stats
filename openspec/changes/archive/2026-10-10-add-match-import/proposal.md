# Proposal

## Why

Сейчас демку надо сначала скачать с FastCup или Cybershoke к себе, а потом загрузить в сервис. Получается двойная передача 130–400 МБ на каждую карту. У Cybershoke прямую ссылку на файл даже нельзя скопировать: кнопка «Download demo» работает через JavaScript.
Проверка показала, что обе платформы отдают ссылку на демку по номеру матча без авторизации, а сам файл скачивается обычным GET. Поэтому сервис может сам забирать демки по ссылке на страницу матча, в том числе все карты серии Bo3/Bo5.

## What Changes

- На странице сессии под зоной загрузки файлов, через «или», появляется поле «Ссылка на матч — демку скачаем сами» (по макету «09 Загрузка демок»). В поле можно вставить несколько ссылок через пробел или с новой строки: они станут матчами в порядке вставки.
- Принимаются только ссылки на страницы матчей FastCup (`cs2.fastcup.net/matches/{id}`) и Cybershoke (`cybershoke.net[/{язык}]/match/{id}`). Остальные ссылки отклоняются сразу, с примером допустимой.
- **Проверка при добавлении** («Проверяем…»): сервис сразу спрашивает у платформы, что матч существует, закончен и его демка доступна. Если нет, ошибка видна под полем, а загрузка не создаётся.
- Прошедшие проверку ссылки скачиваются **в фоне**. Скачивания выполняются по одному, в порядке добавления, и переживают перезапуск сервиса.
- **Серии Bo3/Bo5:**
  - каждая сыгранная карта становится отдельным матчем сессии в порядке карт;
  - у FastCup это демка на каждую карту, у Cybershoke — один zip с `.dem` на каждую карту.
- **Порядок по времени игры.** Матч из ссылки встаёт в сессии на место по времени начала своей карты у платформы: перед первым матчем с более поздним известным временем, иначе в конец. Это работает для ссылок, добавленных в разное время, для карт серии и для разных платформ. Матчи из файлов (у них времени нет) не двигаются. Ручная перестановка остаётся.
- Скачанные файлы проходят через существующий приём демок, где те же форматы, лимит размера, распаковка и дедупликация по SHA-256. Дальше матчи обрабатываются как обычно.
- На странице сессии появляется список загрузок по ссылкам:
  - статус («В очереди», «Скачивается» с прогрессом, «Ошибка» с текстом);
  - ссылки на созданные матчи;
  - действия «Повторить», «Отменить», «Убрать».
- Повторная ссылка на матч, который уже скачивается или уже загружен, новую загрузку не создаёт. Под полем показывается подсказка «Матч … уже есть в сессии — матч #N».
- **Отличие от макета.** В макете матч по ссылке сразу становится строкой таблицы матчей со статусом «Скачивается». По решению пользователя скачивания показываются отдельным списком, а строка списка оформлена как в макете. Статусы матчей не меняются.
- Сервис скачивает файлы только с хостов разрешённых платформ, в том числе при редиректах.
- В контексте проекта (`openspec/config.yaml`) снимается принцип «не скрейпим закрытые API платформ». Использовать недокументированные публичные API платформ, чтобы найти демку матча, теперь допустимо.

Не входит:
- Faceit: демки доступны только через Downloads API по заявке, это будет отдельный change;
- ручная загрузка zip с несколькими демками;
- дата матча из данных платформы;
- из макета: статус «Ждём демку» с автоматической проверкой каждые 5 минут в течение 2 часов и автоповтор скачивания при сбое сети (три попытки). В этом change такая ссылка отклоняется при проверке, а ошибка скачивания исправляется кнопкой «Повторить».

## Capabilities

### New Capabilities

- `match-import`: импорт матчей по ссылкам на страницы матчей платформ, то есть разбор одной или нескольких ссылок, проверка матча через API платформы при добавлении, фоновое скачивание с прогрессом, серии Bo3/Bo5, повтор, отмена, удаление, защита от скачивания с чужих хостов и список загрузок на странице сессии.

### Modified Capabilities

- `game-sessions`: «Порядок матчей в сессии» — матчи из ссылок встают по времени игры, а не в конец.

Ручная загрузка файлов (`demo-ingestion`) не меняется, а импорт использует её правила приёма как есть. Статусы матчей (`web-ui`, `match-reprocessing`) не меняются: скачивание показывается отдельным списком, матч появляется только после скачивания. Удаление загрузок вместе с сессией описано в `match-import`.

## Impact

- `internal/store`: миграция `004` (таблица `imports`, колонки `matches.import_id` и `matches.played_at`), вставка матча по времени и функции очереди загрузок.
- Новый пакет `internal/importer`: платформы FastCup и Cybershoke, фоновое скачивание, белый список хостов.
- `internal/ingest`: передача `importID` при приёме. Ручная загрузка не меняется.
- `internal/api`: `POST /api/sessions/{id}/imports`, `POST /api/imports/{id}/retry`, `DELETE /api/imports/{id}`; поле `imports` в `GET /api/sessions/{id}`.
- `cmd/cs2stats`: запуск фонового скачивания рядом с воркером.
- `web`: поле ссылок под `DropZone` по макету и список загрузок на `SessionPage`, опрос, пока идут скачивания.
- Внешние зависимости: недокументированные API `hasura.fastcup.net` (принимает только разрешённые запросы) и `cybershoke.net/api`. Если их фронт изменится, импорт может сломаться, тогда остаётся ручная загрузка.
- `openspec/config.yaml`, `README.md`, `CLAUDE.md`.
