# Design

## Context

Мотивация — в `proposal.md`. Что важно для решения:

- Вход через Steam (`add-steam-auth`) не сделан, пользователей в базе нет. Группа сейчас — только раздел данных, без владельца и прав. Доступ ляжет на неё следующими changes (2.1–2.3 roadmap) без смены модели.
- Вся «глобальная» выборка проходит через несколько мест: `store.MatchFilter.where` (таблица игроков, профиль, разбивки, дуэли и вкладки профиля), `store.ListSessions`, `store.RatingRows`/`RatingSwing` (OVR). Остальное (сессия, матч, их дуэли и расширенная статистика) уже ограничено своим id.
- Рейтинг считается на каждый запрос (`api.ratingBook`), ничего не хранится — разделить его по группам значит передать группу в выборку строк.
- SQLite открыт с `foreign_keys(1)`: `ALTER TABLE … ADD COLUMN` с `REFERENCES` допускает только значение по умолчанию NULL, а пересоздать `sessions` в транзакции миграции нельзя (на неё ссылаются `matches` и `imports`, выключить `foreign_keys` внутри транзакции нельзя).
- Макеты получены (Claude Design, страница «Экраны», лист «17 Группы и доступ»), бриф к ним — `design-brief.md`. Временную версию, которую реализует этот change, описывают доски: шапка во всех S01–S18, S01 / S01e (пустая группа) / S01m (390) / S01n (диалог «Новая группа»), S09 (не найдено), S19 / S19m («Создайте группу»), S20 / S20e (пустая группа) / S20m (390) — страница группы. У досок есть настройка `ver: temp | full`; для этого change смотреть `temp`. Цифры внутри сессии, матча и профиля на досках старые, на реализацию это не влияет.

## Goals / Non-Goals

**Goals:**
- Одна модель группы, на которую потом ложатся владелец, участники, приглашения и `counted` без новой миграции данных сессий.
- Рейтинг и статистика группы считаются теми же функциями, что сейчас, — меняется только выборка.
- После обновления у пользователя всё выглядит как раньше, только внутри группы «Основная».

**Non-Goals:**
- Права доступа, владелец, участники, приглашения, `counted`, `calibration_matches` группы.
- Перенос сессии в другую группу, удаление группы вместе с сессиями.
- Общий матч в нескольких группах: `matches.sha256 UNIQUE` и проверка источника по ссылке остаются глобальными.
- Изменения в парсере, воркере, импорте, CLI; `ProcessingVersion` не поднимается.

## Decisions

### Схема: `groups` и `sessions.group_id`

Миграция `007_groups.sql`:

```sql
CREATE TABLE groups (
    id         INTEGER PRIMARY KEY,
    name       TEXT NOT NULL,
    created_at TEXT NOT NULL
);
INSERT INTO groups (id, name, created_at) VALUES (1, 'Основная', strftime('%Y-%m-%dT%H:%M:%SZ', 'now'));
ALTER TABLE sessions ADD COLUMN group_id INTEGER REFERENCES groups(id);
UPDATE sessions SET group_id = 1;
CREATE INDEX sessions_group ON sessions(group_id, date, id);
```

- `group_id` в схеме допускает NULL из-за ограничения `ADD COLUMN` (см. Context). `NOT NULL` обеспечивает код: `CreateSession` всегда получает группу, а других путей вставки сессий нет. Тест хранилища проверяет, что после миграции у всех сессий есть группа.
- Альтернатива — пересоздать `sessions` с `NOT NULL`: требует выключить `foreign_keys` вне транзакции миграции и переписать механизм миграций ради одной колонки. Не стоит того.
- «Основная» создаётся и на пустой базе: так у новой установки сразу есть куда создать сессию, а сценарий «групп нет» остаётся только после удаления всех групп.
- `ON DELETE` у `group_id` не нужен: группу с сессиями удалить нельзя (`DeleteGroup` проверяет в той же транзакции и возвращает `ErrGroupNotEmpty`, API — 409).
- `GROUPS` — ключевое слово SQLite только в рамках оконных функций, как имя таблицы оно допустимо (проверено на SQLite 3.45: `CREATE TABLE groups` и `JOIN` с ней работают, а `ADD COLUMN … NOT NULL DEFAULT 1 REFERENCES groups(id)` при `foreign_keys=1` падает с «Cannot add a REFERENCES column with non-NULL default value»).

### Выборка по группе в хранилище

- `MatchFilter.GroupID int64` — обязательное поле для запросов игроков: `where` добавляет `s.group_id = ?`. Нулевое значение — без ограничения (нужно только тестам старых функций и CLI). Так фильтр сессий периода чужой группы просто ничего не находит, отдельной проверки не нужно.
- `ListSessions(ctx, groupID)`, `CreateSession(ctx, groupID, date, title)`; `Session` получает поле `GroupID` (`groupId` в JSON), поэтому ответы сессии и матча (`Match` берёт группу через сессию в `getMatch`) содержат группу.
- `RatingRows(ctx, groupID)` и `RatingSwing(ctx, groupID)` — те же запросы с `JOIN sessions` и условием группы.
- Новый файл `internal/store/groups.go`: `ListGroups` (с числом сессий — для меню переключателя), `CreateGroup`, `GetGroup`, `GroupSummary` (число сессий, матчей с результатом и разных игроков в них — для заголовка страницы группы), `RenameGroup`, `DeleteGroup`.
- `latestName` для профиля — по матчам группы (ник в профиле группы).

### API

- `GET/POST /api/groups` (список с `sessionCount`), `GET/PATCH/DELETE /api/groups/{gid}` (`GET` — группа со сводкой `sessionCount`, `matchCount`, `playerCount`).
- `GET/POST /api/groups/{gid}/sessions` вместо `/api/sessions`.
- `GET /api/groups/{gid}/players`, `/api/groups/{gid}/players/{steamId}` и `/duels`, `/fight`, `/weapons`, `/utility` вместо `/api/players…`. Старые маршруты удаляются: клиент один, он в том же бинаре.
- Хелпер `groupFromPath` разбирает `{gid}` и проверяет существование группы (404 «группа не найдена»), дальше в `MatchFilter.GroupID`.
- Маршруты по id сессии, матча и загрузки остаются как есть. `ratingBook(ctx, groupID)` в `getSession` и `getMatch` берёт группу из сессии.
- Название группы: обязательное, `TrimSpace`, не длиннее 100 символов — по образцу `createSessionRequest.normalize`.
- `listSessions` по-прежнему считает лучшего игрока по каждой сессии; рейтинг книги там не используется.

### Адреса и группа во фронте

- Маршруты: `/g/:gid` (сессии), `/g/:gid/sessions/:id`, `/g/:gid/matches/:id`, `/g/:gid/players`, `/g/:gid/players/:steamId[/:tab]`, `/g/:gid/group` (страница группы).
- Адрес страницы группы — `/g/:gid/group` (решение пользователя по вопросу дизайнера). В полной версии `/g/:gid/group` — вкладка «Участники», `/g/:gid/group/invites` и `/g/:gid/group/settings` — остальные. Во временной версии раздел один, и `/g/:gid/group` сразу показывает название и удаление. Альтернатива дизайнера `/settings`, `/settings/members` отклонена: в полной версии по адресу «settings» открывались бы участники.
- Помощник `web/src/groups.ts`: `useGroupId()` из адреса и функции адресов (`sessionPath(gid, id)`, `playerPath(gid, steamId, tab?)` …). Все ≈40 внутренних ссылок переходят на них — так ссылка не может «выпасть» из группы. Компоненты `ui/` (`Rivals`, `DuelMatrix`, `UploadList`), которые сейчас собирают адрес сами, получают готовый адрес или функцию адреса пропсом, чтобы не зависеть от роутера.
- Альтернатива — оставить сессии и матчи без `/g/` (они и так знают группу по id). Отклонена: переключатель, навигация «Сессии · Игроки · Группа» и ссылки на профиль на этих страницах всё равно нужны группе, а единый префикс проще проверять.
- Несовпадение группы: страница сессии и матча после загрузки сравнивает `groupId` ответа с `:gid` и делает `navigate(…, { replace: true })` на правильный адрес. Старые `/sessions/:id` и `/matches/:id` — те же страницы без `:gid`, поэтому перенаправляются тем же кодом. Ссылка «уже было» в результате загрузки дубликата ведёт на `/matches/:id`: матч может быть в другой группе, страница сама перейдёт в нужную.
- Последняя группа — в `localStorage` (как свёрнутость матрицы дуэлей, `try/catch`). `/`, `/players…` без группы: последняя сохранённая, если она есть в `GET /api/groups`, иначе первая; групп нет — экран «Создайте группу» по S19 (карточка по центру с полем названия, без навигации в шапке). Страница «не найдено» (S09) ведёт «К сессиям» и «К игрокам» в последнюю открытую группу.
- Шапка по макету: `лого / [название группы ⇅]` и навигация «Сессии · Игроки · Группа». На 390 px навигация переносится второй строкой, переключатель остаётся в первой. Меню переключателя (Headless UI `Menu`): заголовок «Группы», группы с числом сессий («4 сессии», «нет сессий»), галочка у текущей, длинные названия обрезаются с подсказкой, затем «Новая группа». Новый компонент `ui/GroupSwitcher.tsx` из токенов `@theme`; стили меню взять с листа «17 Группы и доступ». Диалог «Новая группа» (S01n) — `FormDialog` + `Field`: подзаголовок «У группы свои сессии, игроки и рейтинг. OVR считается только по матчам этой группы.», счётчик «N / 100», ошибка «Введите название группы». Список групп грузится в `Layout` и обновляется после создания, переименования и удаления.
- Решения дизайнера, общие для временной версии: всё, что требует входа, не показывается совсем (без неактивных кнопок); название группы в заголовке «Сессии» не повторяется — оно в переключателе; полоса вкладок при одном разделе не показывается.
- Страница группы (S20, S20e, S20m): заголовок — название группы с карандашом и правкой на месте (`InlineEdit`, как у названия сессии), мета «4 сессии · 21 матч · 19 игроков» из `GET /api/groups/{gid}`; ниже карточка «Опасная зона». Если в группе есть сессии, кнопка «Удалить группу» неактивна с текстом «Удалить можно только группу без сессий. В этой группе N сессий — сначала удалите их.» У пустой группы — `ConfirmDialog` «Группа пустая: в ней нет сессий и матчей. После удаления откроется другая группа.» Ответ 409 (сессию добавили, пока диалог был открыт) показывается в диалоге: «Пока окно было открыто, в группу добавили сессию.» Состояния загрузки и ошибки «Не удалось загрузить группу.» — как у остальных страниц (`PageError`). В полной версии на этой странице появятся вкладки участников и приглашений, поэтому название и удаление не размещаются на странице сессий.
- Фильтр периода по сессиям (`PeriodFilter`) берёт сессии текущей группы.

## Risks / Trade-offs

- [Пропущенная ссылка без группы во фронте ведёт на старый адрес] → старые адреса всё равно перенаправляются; при проверке пройти все страницы headless-браузером и искать `href` без `/g/`.
- [NULL в `sessions.group_id` при будущей ошибке кода] → единственная вставка сессий в `CreateSession` с обязательной группой; тест миграции и тест `CreateSession`.
- [Дубликат из другой группы раскрывает её существование] → пока нет авторизации и все группы видны всем, это не утечка. Когда у групп появится доступ (после `add-steam-auth`), ответ дубликата нужно будет обезличить, как записано в roadmap 2.2.
- [Две группы с одинаковыми названиями в переключателе путаются] → названия не уникальны по решению спеки; в меню видно число сессий.

## Migration Plan

- Миграция `007` применяется при старте автоматически, существующие сессии — в группе 1 «Основная». Демки не пересчитываются.
- Откат: прежний бинарь работает с базой после `007` (лишняя таблица и колонка ему не мешают), но новые группы для него не видны — все сессии снова в одном списке.
- E2E: копия рабочей `data/` в отдельном контейнере — OVR и таблица игроков «Основной» совпадают с текущими значениями.
