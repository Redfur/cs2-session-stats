# Spec Delta

## Purpose

Общие правила веб-интерфейса cs2stats: оформление, адаптивность, поведение таблиц статистики, подтверждение
опасных действий и отображение статусов. Отдельные экраны описаны в спеках своих capability.

## ADDED Requirements

### Requirement: Оформление интерфейса
Интерфейс SHALL использовать единую тёмную тему: цвета, шрифты, отступы и радиусы задаются общими токенами.
Шрифты MUST поставляться вместе с приложением без запросов к внешним сервисам и поддерживать кириллицу.
Числа в таблицах и показателях MUST выводиться моноширинными цифрами и выравниваться по правому краю.

#### Scenario: Работа без доступа в интернет
- **WHEN** сервис запущен в сети без доступа к внешним сайтам
- **THEN** страницы отображаются с фирменными шрифтами, браузер не обращается к внешним адресам

#### Scenario: Выравнивание чисел
- **WHEN** в таблице выводятся значения 9.8 и 114.0
- **THEN** цифры стоят в одних разрядах и выровнены по правому краю колонки

### Requirement: Адаптивная раскладка
Интерфейс SHALL работать при ширине окна от 390 px. У страницы MUST NOT появляться горизонтальная прокрутка:
широкие таблицы прокручиваются по горизонтали внутри своего блока, действия в заголовке переносятся под него.

#### Scenario: Таблица на телефоне
- **WHEN** итоги сессии открыты на экране шириной 390 px
- **THEN** таблица прокручивается по горизонтали внутри карточки, а страница целиком по горизонтали не прокручивается

### Requirement: Сортировка таблиц статистики
Таблицы статистики SHALL сортироваться по клику на заголовок колонки. Без выбора пользователя действует
порядок, заданный для таблицы (для таблиц игроков — rating по убыванию). Первый клик по числовой колонке
сортирует по убыванию, по текстовой — по алфавиту. Повторный клик меняет направление. Активная колонка и
направление MUST быть видны в заголовке.

#### Scenario: Сортировка по ADR
- **WHEN** пользователь нажимает на заголовок «ADR» в итогах сессии
- **THEN** строки упорядочиваются по ADR от большего к меньшему, у заголовка «ADR» отображается стрелка вниз

#### Scenario: Смена направления
- **WHEN** таблица уже отсортирована по ADR по убыванию и пользователь снова нажимает «ADR»
- **THEN** строки упорядочиваются по ADR от меньшего к большему

#### Scenario: Сортировка по нику
- **WHEN** пользователь нажимает на заголовок «Игрок»
- **THEN** строки упорядочиваются по нику по алфавиту

#### Scenario: Таблица со своим порядком по умолчанию
- **WHEN** открыт список матчей профиля игрока без выбранной сортировки
- **THEN** матчи идут от новых к старым, как задано для этой таблицы

### Requirement: Сортировка в адресе страницы
Интерфейс SHALL хранить выбранную сортировку каждой таблицы страницы в адресе страницы, чтобы ссылка и
переход «назад» восстанавливали её. Сортировка по умолчанию в адрес не пишется. Неизвестная колонка в адресе
MUST игнорироваться, и тогда применяется порядок по умолчанию.

#### Scenario: Ссылка с сортировкой
- **WHEN** пользователь открывает ссылку на страницу сессии с сортировкой по KAST по возрастанию
- **THEN** итоги сессии показаны отсортированными по KAST по возрастанию

#### Scenario: Неизвестная колонка
- **WHEN** в адресе указана сортировка по несуществующей колонке
- **THEN** таблица отсортирована по rating по убыванию, ошибки не показывается

### Requirement: Закреплённая колонка игрока
При горизонтальной прокрутке таблицы статистики колонка «Игрок» SHALL оставаться видимой у левого края.

#### Scenario: Прокрутка вправо
- **WHEN** на узком экране пользователь прокручивает таблицу итогов до колонки «Rating»
- **THEN** ник игрока в каждой строке остаётся видимым

### Requirement: Шкала показателей
Интерфейс SHALL окрашивать значения rating, K/D, ADR и KAST по фиксированным порогам, одинаковым на всех
экранах: rating и K/D ниже 0.85 — «плохо», выше 1.15 — «хорошо»; ADR ниже 60 и выше 90; KAST ниже 65% и выше
75%. Граничные значения относятся к «средне». Остальные показатели не окрашиваются. Уровень MUST отличаться не
только оттенком.

#### Scenario: Хороший rating
- **WHEN** у игрока rating 1.51
- **THEN** значение показано как «хорошо»

#### Scenario: Граница порога
- **WHEN** у игрока K/D ровно 0.85 и ADR ровно 90
- **THEN** оба значения показаны как «средне»

#### Scenario: Неокрашиваемый показатель
- **WHEN** у игрока HS% равен 59%
- **THEN** значение показано обычным цветом текста

### Requirement: Подтверждение действий
Необратимые и массовые действия (удаление сессии, удаление матча, пересчёт сессии) SHALL подтверждаться в
модальном диалоге внутри страницы. Диалог называет объект и последствия. Отмена, Esc и клик вне диалога
ничего не меняют. При ошибке запроса диалог остаётся открытым и показывает текст ошибки. В диалоге удаления
фокус при открытии стоит на «Отмена».

#### Scenario: Отмена удаления клавишей Esc
- **WHEN** пользователь открыл диалог удаления матча и нажал Esc
- **THEN** диалог закрывается, матч не удаляется

#### Scenario: Enter не удаляет
- **WHEN** открыт диалог удаления сессии и пользователь сразу нажимает Enter
- **THEN** срабатывает «Отмена», сессия не удаляется

#### Scenario: Ошибка при подтверждении
- **WHEN** пользователь подтвердил удаление, а сервер вернул ошибку
- **THEN** диалог остаётся открытым и показывает текст ошибки сервера

### Requirement: Отображение статуса обработки
Интерфейс SHALL показывать статус матча бейджем с иконкой и подписью: «В очереди», «Обрабатывается»,
«Готово», «Ошибка», а для матча с прежним результатом — «Пересчёт в очереди» и «Пересчитывается». У статуса
«Ошибка» MUST быть виден текст ошибки обработки.

#### Scenario: Пересчёт матча с результатом
- **WHEN** у матча есть результат и он стоит в очереди на обработку
- **THEN** бейдж показывает «Пересчёт в очереди», а счёт матча остаётся видимым

#### Scenario: Ошибка обработки
- **WHEN** обработка матча без результата завершилась ошибкой «в демке нет сыгранных раундов матча»
- **THEN** бейдж показывает «Ошибка», под ним виден текст ошибки

### Requirement: Пустые состояния и ошибки загрузки страницы
Каждая таблица или список без данных SHALL показывать, почему пусто, и следующий шаг. Ошибка загрузки
страницы MUST показывать текст ответа сервера и способ повторить или вернуться к списку. Для неизвестного
адреса показывается страница «не найдено» со ссылками на список сессий и на игроков.

#### Scenario: Неизвестный адрес
- **WHEN** пользователь открывает несуществующий адрес интерфейса
- **THEN** он видит «Страница не найдена» и ссылки на сессии и игроков

#### Scenario: Сервер вернул ошибку
- **WHEN** страница сессии не загрузилась из-за ошибки сервера
- **THEN** страница показывает текст ошибки и кнопку повтора
