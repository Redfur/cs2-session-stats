# Proposal

## Why

Сейчас у игрока есть только HLTV Rating 1.0 за матч, сессию или период. По нему не видно общий уровень игрока, не видно, сыграл ли он лучше обычного, и неясно, как поменялся уровень за вечер. Это первый шаг этапа 1 дорожной карты (`openspec/roadmap.md`, пункт 1.1). На него опираются история рейтинга, подбор составов, карточка и роль игрока.

## What Changes

- **Rating 2.0 вместо 1.0** во всех таблицах и итогах: матч, сессия, игроки, профиль, разбивки, лучший игрок сессии. Формула HLTV Rating 2.0 восстановлена по awpy. Поле `rating` в API остаётся, меняется только его значение. Пороги шкалы «плохо / средне / хорошо» сверяются с распределением Rating 2.0 на данных компании.
- **Шкала 0–100** (`score`): S-образная функция от Rating 2.0, одна для всех. Оценка за матч, за сессию и за период — `score` от суммы счётчиков.
- **OVR** — общий уровень игрока: экспоненциальное скользящее среднее Rating 2.0 по всем его матчам в порядке игры (дата сессии, сессия, номер матча), с весом по числу раундов. Пока у игрока меньше 10 матчей, OVR помечен «калибровка». Порог задаётся переменной окружения `RATING_CALIBRATION_MATCHES`.
- **Среднее за последние 20** — `score` от суммы счётчиков последних 20 матчей игрока.
- **Лучше или хуже обычного:** оценка за матч или сессию сравнивается с OVR до этого матча или сессии.
- **Изменение OVR за сессию:** OVR перед первым матчем игрока в сессии и после последнего («65 → 67, +2»). В первой сессии игрока вместо изменения показывается «калибровка».
- Всё считается при чтении из сохранённых счётчиков, без миграции и без подъёма `ProcessingVersion`. Перестановка, удаление и пересчёт матчей автоматически меняют OVR.
- **Средний OVR команды перед матчем** у названия команды на странице матча, с пометкой «по N из M», если у кого-то это первый матч.
- **UI по макетам Claude Design** (бриф — `design-brief.md`): своя градация оценки из пяти ступеней, отдельная от шкалы метрик; колонка OVR в таблице игроков; три плитки в профиле; вид итогов сессии «Оценки»; колонка «Оценка» в матче и разбивках профиля.

Вне объёма: разложение изменения OVR по слагаемым формулы («за что минус») — отдельный change. Также вне объёма история на графике (1.2), проверка на прошлых матчах и подбор констант по ней (1.3), поправка на силу соперников.

## Capabilities

### New Capabilities
- `player-rating`: Rating 2.0, шкала 0–100, оценки за матч, сессию и период, OVR с калибровкой, среднее за 20, сравнение с обычным уровнем, изменение OVR за сессию, их вывод в API и интерфейсе.

### Modified Capabilities
- `match-stats`: требование «Rating» — HLTV Rating 2.0 (восстановленная формула) вместо 1.0.

## Impact

- `internal/stats`: формула Rating 2.0 и шкала `score`. Rating 1.0 остаётся функцией для сравнения в 1.3 и в API не выводится.
- Новый пакет `internal/rating`: проход по матчам в порядке игры, OVR, оценки, сравнения.
- `internal/store`: выборка счётчиков всех матчей с результатом в порядке игры.
- `internal/config`: `RATING_CALIBRATION_MATCHES` (по умолчанию 10).
- `internal/api`: новые поля в ответах `GET /api/players`, `GET /api/players/{steamId}`, `GET /api/sessions/{id}`, `GET /api/matches/{id}` (в том числе средний OVR команд). Старые поля остаются, `rating` теперь Rating 2.0.
- `web/`: `metrics.ts` (пороги), подписи «HLTV 1.0» → «Rating 2.0», токены `--color-ovr-1…5`, компоненты `ScoreBadge`, `VsUsual`, `OvrChange`, `OvrTooltip`, новые элементы на четырёх экранах.
- Документация: `README.md`, `CLAUDE.md` (инвариант «Rating — HLTV 1.0»), `openspec/roadmap.md` (статус).
