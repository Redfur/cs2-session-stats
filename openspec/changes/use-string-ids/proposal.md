# Proposal

## Why

Группы, сессии, матчи и загрузки адресуются последовательными целыми числами (1, 2, 3…), и эти числа видны в адресах страниц, путях API, ответах и телах запросов. Любой объект находится перебором соседних номеров, а по номеру видно, сколько объектов в сервисе. В будущем API может стать публичным или доступным по API key, поэтому идентификаторы объектов должны быть неугадываемыми уже сейчас, пока данных и внешних ссылок мало.

## What Changes

- **BREAKING (API, адреса UI, БД):** идентификатор группы, сессии, матча и загрузки — строка: префикс типа и 12 случайных символов base62 (`g_k3Xq9wTb2LpA`, `s_…`, `m_…`, `imp_…`), около 71 бита случайности. Он же — первичный ключ в базе; целых id у этих объектов не остаётся.
- Во всех путях API, телах запросов (порядок матчей) и ответах (`id`, `groupId`, `sessionId`, `matchId`, `importId`) — только строковые id. Числовой id или id с префиксом другого типа даёт «не найдено», как отсутствующий объект. SteamID игроков не меняются.
- Старые числовые адреса (`/g/1/sessions/3`) не принимаются и не перенаправляются (решение пользователя: перенаправление вернуло бы перебор). Сохранённая в браузере последняя группа, которой больше нет, заменяется первой доступной.
- Миграция выдаёт существующим объектам новые id, сохраняя все связи и порядок: списки, очереди обработки и скачивания, хронология рейтинга остаются прежними, статистика и OVR не меняются.
- CLI `cs2stats reparse --session ID | --match ID` принимает строковые id.

Вне объёма: публичное API и API key, перенос сессии между группами, публичный код группы для запроса доступа (roadmap 2.6), смена идентификации игроков.

## Capabilities

### New Capabilities
- `object-ids`: формат и свойства идентификаторов групп, сессий, матчей и загрузок — неугадываемость, префикс типа, отказ на числовые и чужие id, отсутствие числовых id объектов в API, сохранение данных и порядка при переходе.

## Impact

- **БД:** миграция `008` пересобирает `groups`, `sessions`, `matches`, `imports` и таблицы результатов матча (`match_players`, `match_duels`, `match_player_ext`, `match_player_weapons`, `match_rounds`, `match_kills`, `match_clutches`) со строковыми ключами; раннер миграций получает Go-шаг для генерации id. `ProcessingVersion` не поднимается, демки не пересчитываются.
- **Go:** новый пакет `internal/ids`; тип id `int64` → `string` в `internal/store`, `internal/api`, `internal/worker`, `internal/importer`, `internal/ingest`, `internal/rating`, `cmd/cs2stats` (reparse).
- **Фронт:** типы id в `web/src/api.ts` и компонентах — строки; последняя группа из localStorage проверяется по списку групп. Форма адресов `paths` не меняется.
- **Документация:** `CLAUDE.md` (инварианты id и порядка), `README.md` (примеры адресов и `reparse`).
- Внешние закладки с числовыми адресами перестанут открываться.
