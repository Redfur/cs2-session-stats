## 2. На что опирается после `add-groups`

- Таблица `groups (id, name, created_at)`, `sessions.group_id` (в схеме допускает NULL из-за ограничения `ADD COLUMN … REFERENCES`, `NOT NULL` обеспечивает код), группа 1 «Основная» из миграции `007`.
- API: данные группы — под `/api/groups/{gid}/…`; сессии, матчи и загрузки — по своему id, группа берётся из сессии. Это две точки, где появится проверка доступа.
- Ответ 404 «группа не найдена» уже одинаков для чужой и несуществующей группы.
- Адреса UI `/g/:gid/…`, страница группы `/g/:gid/group`; в полной версии вкладки `/g/:gid/group` (участники), `/group/invites`, `/group/settings`.
- Последняя открытая группа хранится в `localStorage`.
- Дедупликация демок и источников ссылок глобальная; ответ дубликата сейчас ссылается на матч, даже если он в другой группе.
- Удаление группы во временной версии — только пустой.

## 3. Принятые решения

- **Гость** видит только экран «Войти через Steam» без лендинга. Любой внутренний адрес ведёт на вход и после входа возвращает обратно.
- **Роли:** владелец (один на группу) и участник. Читать данные группы могут только участники, менять — только владелец. Матрица прав — бриф, раздел 3.
- **Вступление** только по приглашению и с согласия: автоприглашения игрокам из матчей, адресное приглашение владельца, ссылка-приглашение (срок, лимит, отзыв).
- **Автоприглашения** — настройка группы, по умолчанию включены. Включение действует на всех уже найденных игроков. Запрета для отдельного игрока нет.
- **Отказ** скрывает группу; передумать сам нельзя, вернуть может только владелец новым приглашением. Скрыть свою статистику в чужой группе нельзя.
- **Только чтение:** без отдельной плашки — бейдж «участник» у названия группы, кнопки изменения скрыты.
- **Страница группы:** участники (передать владение, удалить участника, выйти; владелец выходит только после передачи), приглашения, настройки (название, автоприглашения, порог калибровки). У участника — только список участников, без вкладок.
- **Удаление группы** в полной версии — вместе с сессиями и матчами, подтверждение вводом названия.
- **Учёт матча** `matches.counted`: исключённый матч виден с меткой «не учитывается», но не входит в статистику, рейтинг и дуэли группы; переключает владелец; подсказка про новых игроков в матче.
- **Порог калибровки группы** `groups.calibration_matches`, NULL — значение сервиса.
- **Профиль:** переключатель «Статистика в группе: A / B» по группам, где зритель участник и игрок играл; общей цифры нет.
- **Дубликат** из чужой группы — без названия и ссылки на неё; после 2.4 — «Подключён» без повторной загрузки.
- Уведомлений вне сервиса нет. Администратора сервиса и запросов доступа (2.6) пока нет.

## 5. Открытые вопросы (решить при propose)

- Кто станет владельцем «Основной» и других групп, созданных до входа: параметр конфигурации, первый вошедший, первый из `ALLOWED_STEAM_IDS`?
- Нужен ли `ALLOWED_STEAM_IDS` после появления участников и приглашений; может ли любой вошедший создавать группы.
- Объединять ли вход и права доступа в один change или идти нарезкой из раздела 4. Если вход раньше прав, что видит вошедший не владелец в промежутке.
- Что работает без входа: CLI (`parse`, `reparse`), служебные маршруты (проверка живости). Как тестировать API с сессией входа.
- Срок жизни сессии входа и продление; ник и аватар без `STEAM_API_KEY` (из последней демки?).
- Отметка прочтения уведомлений: `seen_at` у приглашений или отдельная таблица.
- Текст ответа дубликата из чужой группы до 2.4.
- Связь пользователя и игрока: SteamID64 один и тот же — нужно ли что-то ещё (например, игрок без матчей в группе, приглашённый по ссылке).
- Лимиты и хранение для публичного деплоя — отдельный этап 2.5.
