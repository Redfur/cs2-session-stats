# game-sessions Specification

## Purpose

Позволяет объединять матчи одного игрового вечера компании друзей в сессию и видеть итоги вечера по каждому игроку.

## Requirements

### Requirement: Создание сессии
Система SHALL позволять создать сессию с датой и необязательным названием. Если дата не указана, используется текущая дата сервера. Если название не указано, отображается дата сессии.

#### Scenario: Создание сессии с датой и названием
- **WHEN** пользователь создаёт сессию с датой 2026-10-08 и названием «Четверговый микс»
- **THEN** система сохраняет сессию и возвращает её идентификатор, дату и название

#### Scenario: Создание сессии без параметров
- **WHEN** пользователь создаёт сессию без даты и названия
- **THEN** система создаёт сессию с текущей датой и пустым названием

#### Scenario: Некорректная дата
- **WHEN** пользователь передаёт дату в неверном формате
- **THEN** система отклоняет запрос с ошибкой валидации и не создаёт сессию

### Requirement: Список сессий
Система SHALL показывать список всех сессий, отсортированный по дате от новых к старым, с количеством матчей в каждой.

#### Scenario: Просмотр списка
- **WHEN** существуют сессии от 2026-10-01 и 2026-10-08
- **THEN** список показывает сессию от 2026-10-08 первой, для каждой указаны дата, название и число матчей

#### Scenario: Пустой список
- **WHEN** сессий ещё нет
- **THEN** система возвращает пустой список, а интерфейс предлагает создать первую сессию

### Requirement: Порядок матчей в сессии
Система SHALL упорядочивать матчи внутри сессии по порядку загрузки: в пределах одной загрузки — по порядку файлов, догруженные матчи идут после уже существующих. Номера матчей сессии MUST идти подряд с 1: после удаления или перестановки матча они пересчитываются.

#### Scenario: Порядок при загрузке нескольких файлов
- **WHEN** в сессию за одну загрузку переданы файлы A, B, C
- **THEN** матчи сессии нумеруются 1 — A, 2 — B, 3 — C

#### Scenario: Догрузка в существующую сессию
- **WHEN** в сессию с матчами A, B догружается файл C
- **THEN** C получает номер 3

#### Scenario: Перенумерация после удаления
- **WHEN** из сессии с матчами 1 — A, 2 — B, 3 — C удалён матч B
- **THEN** матчи сессии нумеруются 1 — A, 2 — C, а следующий загруженный файл получает номер 3

### Requirement: Сводная статистика игроков за сессию
Система SHALL показывать на странице сессии таблицу игроков, участвовавших хотя бы в одном матче сессии с посчитанным результатом, с агрегатами: число матчей, победы, K, D, A, K/D, ADR, HS%, KAST и средний rating. В агрегаты входят все матчи с результатом, включая пересчитываемые и матчи с неудачным пересчётом. Матчи без результата не входят.

#### Scenario: Агрегация по нескольким матчам
- **WHEN** игрок сыграл в сессии 2 матча: 20 раундов с суммарным уроном 1600 и 30 раундов с уроном 2400
- **THEN** ADR игрока за сессию равен (1600 + 2400) / (20 + 30) = 80

#### Scenario: Средневзвешенные проценты
- **WHEN** KAST и HS% считаются за сессию
- **THEN** они вычисляются по суммарным раундам и убийствам всех матчей, а не как среднее процентов

#### Scenario: Rating за сессию
- **WHEN** игрок сыграл несколько матчей
- **THEN** rating за сессию взвешивается по количеству раундов в каждом матче

#### Scenario: Неготовые матчи исключены
- **WHEN** в сессии один матч `done` и один `failed` при первой обработке (результата у него нет)
- **THEN** сводная таблица строится только по матчу `done`

#### Scenario: Матч в пересчёте или с неудачным пересчётом
- **WHEN** у матча есть результат, а сам он стоит в очереди на пересчёт или его пересчёт завершился ошибкой
- **THEN** его прежний результат входит в сводную таблицу

#### Scenario: Игрок идентифицируется по SteamID64
- **WHEN** игрок сменил ник между матчами
- **THEN** его статистика объединяется в одну строку, отображается ник из последнего по порядку матча

### Requirement: Просмотр сессии
Система SHALL показывать на странице сессии её дату, название, список матчей с номером, картой, счётом и статусом обработки, а также сводную таблицу игроков.

#### Scenario: Сессия с матчами в обработке
- **WHEN** часть матчей сессии ещё в статусе `pending` или `parsing`
- **THEN** страница показывает их статус и обновляет данные, пока обработка не завершится

#### Scenario: Несуществующая сессия
- **WHEN** запрошена сессия с неизвестным идентификатором
- **THEN** система возвращает ошибку «не найдено»

### Requirement: Редактирование сессии
Система SHALL позволять изменить дату и название существующей сессии. Правила валидации те же, что при создании: дата в формате ГГГГ-ММ-ДД, название не длиннее 200 символов. Пустое название допустимо, тогда отображается дата. Матчи и статистика сессии при редактировании не меняются.

#### Scenario: Изменение названия и даты
- **WHEN** пользователь меняет у сессии от 2026-10-08 название на «Пятничный микс» и дату на 2026-10-09
- **THEN** система сохраняет новые значения, а список сессий показывает её под датой 2026-10-09

#### Scenario: Некорректная дата при редактировании
- **WHEN** пользователь передаёт дату в неверном формате
- **THEN** система отклоняет запрос с ошибкой валидации, сессия не меняется

#### Scenario: Редактирование несуществующей сессии
- **WHEN** запрошено изменение сессии с неизвестным идентификатором
- **THEN** система возвращает ошибку «не найдено»

### Requirement: Удаление сессии
Система SHALL позволять удалить сессию вместе со всеми её матчами, статистикой этих матчей и файлами их демок. Удаление необратимо. Интерфейс MUST запрашивать подтверждение и показывать в нём число матчей сессии.

#### Scenario: Удаление сессии с матчами
- **WHEN** пользователь подтверждает удаление сессии с тремя матчами
- **THEN** сессия исчезает из списка, её матчи и их статистика больше не доступны, а статистика игроков по остальным сессиям не меняется

#### Scenario: Удаление пустой сессии
- **WHEN** пользователь удаляет сессию без матчей
- **THEN** сессия исчезает из списка

#### Scenario: Отказ от подтверждения
- **WHEN** пользователь отменяет подтверждение удаления
- **THEN** сессия и её матчи остаются без изменений

#### Scenario: Удаление несуществующей сессии
- **WHEN** запрошено удаление сессии с неизвестным идентификатором
- **THEN** система возвращает ошибку «не найдено»

### Requirement: Удаление матча
Система SHALL позволять удалить отдельный матч сессии вместе с его статистикой и файлом демки, независимо от статуса обработки. Интерфейс MUST запрашивать подтверждение. Итоги сессии после удаления строятся без этого матча.

#### Scenario: Удаление обработанного матча
- **WHEN** пользователь подтверждает удаление матча №2 из сессии с матчами 1, 2, 3
- **THEN** матч и его статистика больше не доступны, итоги сессии и статистика игроков считаются без него

#### Scenario: Удаление матча во время обработки
- **WHEN** пользователь удаляет матч в статусе `pending` или `parsing`
- **THEN** матч удаляется, а завершение его обработки не создаёт заново ни матч, ни его статистику

#### Scenario: Удаление несуществующего матча
- **WHEN** запрошено удаление матча с неизвестным идентификатором
- **THEN** система возвращает ошибку «не найдено»

### Requirement: Изменение порядка матчей
Система SHALL позволять менять порядок матчей внутри сессии: в интерфейсе матч сдвигается на одну позицию вверх или вниз. Новый порядок задаётся полным списком матчей сессии. Список, который не совпадает с набором её матчей, система MUST отклонять без изменений.

#### Scenario: Сдвиг матча вверх
- **WHEN** в сессии матчи 1 — A, 2 — B, 3 — C, и пользователь сдвигает C вверх
- **THEN** матчи сессии нумеруются 1 — A, 2 — C, 3 — B

#### Scenario: Неполный или чужой список матчей
- **WHEN** в запросе нового порядка не хватает матча сессии или есть матч другой сессии
- **THEN** система отклоняет запрос с ошибкой валидации, порядок не меняется
