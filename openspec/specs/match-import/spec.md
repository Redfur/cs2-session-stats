# match-import Specification

## Purpose

Импорт матчей по ссылке на страницу матча платформы. Сервис сам проверяет матч, в фоне скачивает его демки, включая все карты серии Bo3/Bo5, и добавляет их в сессию как обычные загрузки.

## Requirements

### Requirement: Добавление матчей по ссылкам
Система SHALL принимать в существующую сессию одну или несколько ссылок на страницы матчей, разделённых пробелами или переводами строк. Ссылки обрабатываются в порядке ввода, и для каждой в ответе есть отдельный результат: принята, уже есть или ошибка. Пробелы по краям, протокол `http`, `www.`, языковой префикс пути, параметры и фрагмент адреса MUST NOT мешать распознаванию.

#### Scenario: Одна ссылка FastCup
- **WHEN** пользователь добавляет в сессию `https://cs2.fastcup.net/matches/27802385`
- **THEN** создаётся загрузка FastCup с номером матча 27802385 в статусе «в очереди»

#### Scenario: Ссылка Cybershoke с языком
- **WHEN** пользователь добавляет `https://cybershoke.net/ru/match/12578063?tab=stats`
- **THEN** создаётся загрузка Cybershoke с номером матча 12578063

#### Scenario: Несколько ссылок
- **WHEN** пользователь добавляет три ссылки, разделённые переводами строк, и вторая из них ведёт на чужой сайт
- **THEN** первая и третья ссылки становятся загрузками, результаты в ответе идут в порядке ввода, для второй указана ошибка

#### Scenario: Несуществующая сессия
- **WHEN** ссылки добавляются в неизвестную сессию
- **THEN** запрос отклоняется с ошибкой «не найдено», загрузки не создаются

### Requirement: Поддерживаемые платформы
Система SHALL принимать только ссылки на страницы матчей FastCup (`cs2.fastcup.net/matches/{номер}`) и Cybershoke (`cybershoke.net/match/{номер}`). Другие сайты, другие страницы этих сайтов и прямые ссылки на файлы MUST отклоняться сразу, без обращения к платформе. Текст ошибки объясняет, что нужна страница матча, и приводит пример.

#### Scenario: Чужой сайт
- **WHEN** пользователь добавляет `https://example.com/match/1`
- **THEN** ссылка отклоняется с ошибкой и примерами ссылок FastCup и Cybershoke, загрузка не создаётся

#### Scenario: Профиль вместо матча
- **WHEN** пользователь добавляет `https://cs2.fastcup.net/profile/1873320`
- **THEN** ссылка отклоняется с текстом «Это ссылка на профиль, а не на матч. Нужна страница матча, например https://cs2.fastcup.net/matches/<номер>»

#### Scenario: Faceit пока не поддерживается
- **WHEN** пользователь добавляет ссылку на комнату Faceit
- **THEN** ссылка отклоняется с ошибкой о неподдерживаемом сайте

### Requirement: Проверка матча при добавлении
Перед созданием загрузки система SHALL проверить через данные платформы, что матч существует, закончен и его демка доступна. Если это не так, ссылка MUST отклоняться без создания загрузки, с понятной причиной: матч не найден, матч ещё не закончен, демку ещё не выложили, демка удалена платформой по сроку хранения, платформа не ответила или изменила формат ответа. В тексте причины есть совет загрузить файл вручную, если ждать нельзя.

#### Scenario: Матч не закончен
- **WHEN** добавлена ссылка на матч, который ещё идёт
- **THEN** ссылка отклоняется с текстом «матч ещё не закончен», загрузка не создаётся

#### Scenario: Демку ещё не выложили
- **WHEN** матч закончился, но платформа ещё не выложила демку
- **THEN** ссылка отклоняется с текстом, что демку ещё не выложили и ссылку можно добавить позже

#### Scenario: Демка удалена по сроку
- **WHEN** добавлена ссылка на матч FastCup, у которого истёк срок хранения демки
- **THEN** ссылка отклоняется с текстом, что платформа удалила демку, и советом загрузить файл вручную, если он сохранён

#### Scenario: Платформа изменила API
- **WHEN** платформа отвечает ошибкой или ответом неожиданного формата
- **THEN** ссылка отклоняется с текстом, что получить демку с платформы не удалось, и советом загрузить файл вручную

### Requirement: Повторная ссылка на тот же матч
Система MUST NOT создавать вторую загрузку матча платформы, который уже скачивается или из которого есть матч в любой сессии. Результат по такой ссылке — «уже есть» со ссылкой на сессию и матч, а не ошибка. Если у этого матча платформы есть загрузка с ошибкой в той же сессии, повторная ссылка ставит её на повтор. Если матчи из прежней загрузки удалены, ссылку можно добавить снова.

#### Scenario: Матч уже в этой сессии
- **WHEN** из ссылки на матч 26460377 уже создан матч #2 этой сессии, и пользователь добавляет ту же ссылку
- **THEN** загрузка не создаётся, результат «уже есть» ссылается на матч #2 этой сессии

#### Scenario: Матч уже скачивается
- **WHEN** ссылка на матч уже добавлена, скачивание идёт, и пользователь добавляет её снова в эту или другую сессию
- **THEN** загрузка не создаётся, результат «уже скачивается» ссылается на сессию этой загрузки

#### Scenario: Загрузка с ошибкой
- **WHEN** в сессии есть загрузка этого матча со статусом «ошибка», и пользователь добавляет ссылку снова
- **THEN** новая загрузка не создаётся, прежняя ставится в очередь заново

#### Scenario: Матчи удалены
- **WHEN** все матчи, созданные из ссылки, удалены, и пользователь добавляет ссылку снова
- **THEN** создаётся новая загрузка в статусе «в очереди»

### Requirement: Серии Bo3 и Bo5
Для серии система SHALL создавать отдельный матч из каждой сыгранной карты в порядке карт серии. Несыгранные карты серии пропускаются. Каждый файл демки проходит тот же приём, что и ручная загрузка: форматы, лимит размера, распаковка и дедупликация.

#### Scenario: Bo3 Cybershoke 2:0
- **WHEN** добавлена ссылка на Bo3 Cybershoke, закончившуюся 2:0, и платформа отдаёт один архив с демками `map1` и `map2`
- **THEN** в сессии появляются два матча, сначала из `map1`, затем из `map2`

#### Scenario: Bo3 FastCup
- **WHEN** добавлена ссылка на Bo3 FastCup из трёх сыгранных карт
- **THEN** в сессии появляются три матча в порядке номеров карт

#### Scenario: Одна карта уже загружена
- **WHEN** демка второй карты серии уже была загружена вручную
- **THEN** вторая карта отмечена в загрузке как «уже загружена» со ссылкой на существующий матч, остальные карты становятся новыми матчами

### Requirement: Фоновое скачивание
Система SHALL скачивать загрузки в фоне по одной и не ждать скачивания в ответе на добавление ссылок. Загрузки одного ввода встают в очередь по времени игры матча, загрузки разных вводов — в порядке добавления. Статусы загрузки: «в очереди» → «скачивается» → «готово» или «ошибка». Матч создаётся только после скачивания и проверки его демки и дальше обрабатывается как загруженный вручную.

#### Scenario: Ответ до скачивания
- **WHEN** ссылка прошла проверку
- **THEN** ответ с загрузкой в статусе «в очереди» приходит до начала скачивания демки

#### Scenario: Очередь одного ввода
- **WHEN** одним вводом добавлены ссылки на матч B, сыгранный в 21:00, и матч A, сыгранный в 20:00
- **THEN** сначала скачивается A, затем B

#### Scenario: Успешная загрузка
- **WHEN** все демки загрузки скачаны и приняты
- **THEN** загрузка получает статус «готово», её матчи ставятся в обработку

### Requirement: Место матча в сессии по времени игры
Матч из ссылки SHALL получать место в сессии по времени начала своей карты у платформы. Он встаёт перед первым матчем сессии с известным более поздним временем, а если такого нет — в конец. Номера следующих матчей сдвигаются. Время известно только у матчей из ссылок; матчи, загруженные файлом, не двигаются относительно друг друга. При равном времени раньше идёт меньший номер матча платформы, затем меньший номер карты. Порядок можно поменять вручную.

#### Scenario: Ссылки в обратном порядке
- **WHEN** одним вводом добавлены ссылки на матч B (21:00) и матч A (20:00)
- **THEN** после скачивания A — матч 1, B — матч 2

#### Scenario: Более ранний матч добавлен позже
- **WHEN** в сессии матчи 1 — A (20:00) и 2 — B (21:00) из ссылок, а позже добавлена ссылка на матч C (20:30)
- **THEN** C становится матчем 2, B — матчем 3

#### Scenario: Разные платформы
- **WHEN** добавлены ссылка на Cybershoke, сыгранный в 20:00, и на FastCup, сыгранный в 19:00
- **THEN** матч FastCup идёт раньше матча Cybershoke, хотя номера матчей платформ несравнимы

#### Scenario: Карты серии
- **WHEN** добавлена ссылка на Bo3, где карта 1 началась в 20:00, а карта 2 в 20:40
- **THEN** карта 1 идёт раньше карты 2, а матч из другой ссылки, сыгранный в 20:20, встаёт между ними

#### Scenario: Матч из файла
- **WHEN** в сессии 1 — файл F и 2 — матч A из ссылки (21:00), и добавлена ссылка на матч C (20:00)
- **THEN** C встаёт перед A: 1 — F, 2 — C, 3 — A

#### Scenario: Матч из файла после скачивания
- **WHEN** в сессии 1 — матч A из ссылки, затем загружен файл F, а потом скачан матч B из ссылки с более поздним временем, чем A
- **THEN** B встаёт в конец: 1 — A, 2 — F, 3 — B

### Requirement: Ошибки скачивания и частичный результат
Если демку не удалось получить или принять уже после добавления ссылки (платформа не ответила, демка пропала, файл повреждён или больше лимита), загрузка SHALL получать статус «ошибка» с текстом причины. Матчи из уже принятых карт сохраняются. Для каждой карты загрузка показывает результат: принята (со ссылкой на матч), уже загружена (со ссылкой на существующий матч) или ошибка.

#### Scenario: Сайт не ответил
- **WHEN** при скачивании сервер с демкой не отвечает
- **THEN** загрузка получает статус «ошибка» с текстом, что сайт с демкой не ответил и файл не скачан

#### Scenario: Ошибка второй карты
- **WHEN** в Bo3 первая карта принята, а демка второй превышает лимит размера
- **THEN** загрузка получает статус «ошибка» с текстом о превышении размера, матч из первой карты остаётся в сессии

### Requirement: Прогресс скачивания
Пока загрузка скачивается, система SHALL показывать объём уже скачанных данных, а если платформа сообщает размер файла, ещё полный объём и процент. Прогресс обновляется без перезагрузки страницы.

#### Scenario: Размер известен
- **WHEN** скачано 196 МБ файла размером 392 МБ
- **THEN** у загрузки показано 50% и «196 из 392 МБ»

#### Scenario: Размер неизвестен
- **WHEN** платформа не сообщила размер файла, и скачано 120 МБ
- **THEN** у загрузки показано «120 МБ» без процента

### Requirement: Повтор, отмена и удаление загрузки
Система SHALL позволять поставить загрузку со статусом «ошибка» на повтор. Повтор заново получает адреса демок, уже принятые карты отмечаются как «уже загружена». Система SHALL позволять удалить загрузку в любом статусе. Удаление прерывает идущее скачивание. Созданные из загрузки матчи при удалении загрузки остаются.

#### Scenario: Повтор после ошибки сети
- **WHEN** загрузка получила ошибку «сайт с демкой не ответил», и позже пользователь нажимает «Повторить»
- **THEN** загрузка снова встаёт в очередь и, если сайт отвечает, завершается созданием матча

#### Scenario: Отмена скачивания
- **WHEN** пользователь удаляет загрузку, пока идёт скачивание
- **THEN** скачивание прерывается, временные файлы удаляются, матч из незаконченной карты не создаётся

#### Scenario: Удаление завершённой загрузки
- **WHEN** пользователь убирает из списка загрузку со статусом «ошибка», из которой уже создан один матч
- **THEN** загрузка исчезает из списка, матч остаётся в сессии

### Requirement: Загрузки при удалении сессии
При удалении сессии система SHALL удалять все её загрузки и прерывать идущее скачивание.

#### Scenario: Удаление сессии во время скачивания
- **WHEN** пользователь удаляет сессию, загрузка которой скачивается
- **THEN** скачивание прерывается, загрузки сессии удаляются, матчи из неё не создаются

### Requirement: Перезапуск сервиса
Загрузки SHALL переживать перезапуск сервиса. Загрузки «в очереди» сохраняются. Прерванное скачивание после старта ставится в очередь и начинается заново.

#### Scenario: Остановка во время скачивания
- **WHEN** сервис остановлен, пока загрузка скачивалась
- **THEN** после старта загрузка снова встаёт в очередь, частично скачанный файл не используется

### Requirement: Скачивание только с хостов платформ
Система MUST обращаться при импорте только к хостам поддерживаемых платформ (домены `fastcup.net`, `cybershoke.net` и их поддомены), в том числе при перенаправлениях. Скачанный объём MUST ограничиваться лимитом размера демки, превышение прерывает скачивание.

#### Scenario: Перенаправление на чужой хост
- **WHEN** адрес демки отвечает перенаправлением на хост вне списка платформ
- **THEN** скачивание прерывается, загрузка получает статус «ошибка»

#### Scenario: Слишком большой файл
- **WHEN** скачиваемый файл превышает лимит размера демки
- **THEN** скачивание прерывается, временный файл удаляется, загрузка получает статус «ошибка» о превышении размера

### Requirement: Поле ссылки в интерфейсе
На странице сессии интерфейс SHALL показывать под зоной загрузки файлов, через разделитель «или», поле «Ссылка на матч — демку скачаем сами» с кнопкой «Добавить» и подсказкой о нескольких ссылках. Добавление работает по Enter и по кнопке. Ссылки, вставленные с новой строки, MUST разделяться, а не склеиваться. Пока идёт проверка, поле недоступно, а кнопка показывает «Проверяем…».

#### Scenario: Проверка ссылки
- **WHEN** пользователь вставляет ссылку и нажимает Enter
- **THEN** поле блокируется, кнопка показывает «Проверяем…», после ответа поле снова доступно

#### Scenario: Вставка нескольких строк
- **WHEN** пользователь вставляет в поле две ссылки, каждая на своей строке
- **THEN** в поле они разделены пробелом и после добавления обрабатываются как две ссылки

#### Scenario: Все ссылки приняты
- **WHEN** все добавленные ссылки стали загрузками
- **THEN** поле очищается, загрузки появляются в списке загрузок

### Requirement: Результат добавления под полем
Интерфейс SHALL показывать под полем результат по ссылкам, которые не стали новыми загрузками. Ошибка показывается текстом ошибки, при этом поле подсвечивается и в нём остаются только непринятые ссылки. Результат «уже есть» показывается подсказкой со ссылкой на матч или сессию, без подсветки ошибки.

#### Scenario: Ссылка на профиль
- **WHEN** пользователь добавляет ссылку на профиль FastCup
- **THEN** поле подсвечено как ошибочное, под ним текст «Это ссылка на профиль, а не на матч…», ссылка остаётся в поле

#### Scenario: Матч уже в сессии
- **WHEN** сервер ответил, что матч 26460377 уже есть в этой сессии как матч #2
- **THEN** поле очищено, под ним подсказка «Матч 26460377 уже есть в сессии — матч #2. Повторно не добавлен.» со ссылкой на матч

#### Scenario: Часть ссылок с ошибкой
- **WHEN** из трёх ссылок две приняты, а одна отклонена
- **THEN** в поле остаётся только отклонённая ссылка, под полем её ошибка, принятые появились в списке загрузок

### Requirement: Список загрузок в интерфейсе
Интерфейс SHALL показывать на странице сессии загрузки в статусах «в очереди», «скачивается» и «ошибка», а также завершённые загрузки, в которых не все карты стали новыми матчами. Строка показывает ссылку на матч платформы, статус бейджем, прогресс, текст ошибки, результат по картам и действия «Повторить», «Отменить» или «Убрать». Пока есть загрузки в работе, страница обновляет их сама.

#### Scenario: Идёт скачивание
- **WHEN** у загрузки скачано 310 из 690 МБ
- **THEN** строка показывает ссылку, бейдж «Скачивается», полосу 45% и «310 из 690 МБ · качаем на сервере, вкладку можно закрыть»

#### Scenario: Скачивание завершилось
- **WHEN** загрузка Bo1 скачалась и матч принят
- **THEN** загрузка пропадает из списка, а матч появляется в таблице матчей со статусом «В очереди» без перезагрузки страницы

#### Scenario: Матч уже был загружен файлом
- **WHEN** загрузка завершилась, а её единственная демка оказалась уже загруженной
- **THEN** загрузка остаётся в списке с пометкой «уже загружен» и ссылкой на матч, пока пользователь её не уберёт
