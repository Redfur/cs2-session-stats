# CS2 Session Stats

Анализатор демок CS2 для дружеских 5х5. Сервис не собирает статистику по всем матчам игроков, а работает только с играми вашей компании внутри **игровых сессий** (вечеров).

Как это работает:
1. Создаёте сессию: дата и необязательное название.
2. Загружаете в неё демки матчей этого вечера с FastCup, Cybershoke или любые другие `.dem`.
3. Сервис в фоне разбирает каждую демку и показывает scoreboard матча и сводную таблицу игроков за вечер:
   K/D/A, ADR, HS%, KAST, 2K–5K, opening kills/deaths, rating (HLTV 1.0).

## Запуск через Docker

```sh
docker compose up -d --build
```

Откройте http://localhost:8080. Данные (SQLite и исходные демки) хранятся в `./data`.

Контейнер запускается от пользователя с UID/GID `1000`. Если ваш UID другой, задайте `UID` и `GID` в окружении или в файле `.env`.

> ⚠️ **Авторизации нет.** Не открывайте сервис в интернет напрямую: закройте его reverse proxy с basic auth или держите в локальной сети / VPN.

## Где брать демки

У FastCup и Cybershoke нет публичного API для скачивания демок, поэтому их загружают вручную.
Демку можно скачать со страницы матча на платформе. Поддерживаются форматы `.dem`, `.dem.gz`, `.dem.bz2`, `.dem.zst`, а также `.zip` с одной демкой внутри.
Платформы хранят демки ограниченное время, поэтому лучше скачивать их в тот же вечер.

Повторно загруженная демка (та же по содержимому, даже в другом архиве) не создаёт новый матч: сервис покажет ссылку на уже существующий.
Порядок матчей в сессии совпадает с порядком файлов при загрузке.

## Разработка

Нужны Go (версия из `go.mod`) и Node.js 22+. `Makefile` ожидает Go в `~/.local/go/bin` или в `PATH`.

```sh
cd web && npm ci && cd ..   # зависимости фронтенда (один раз)
make dev                    # Go API на :8080 + Vite на :5173 (откройте http://localhost:5173)
make test                   # go vet, go test, проверка типов фронтенда
make build                  # бинарь ./cs2stats со встроенным фронтендом
```

Разобрать демку без запуска сервиса (JSON в stdout):

```sh
go run ./cmd/cs2stats parse path/to/match.dem
```

Проверка парсера на реальной демке. Демки в репозиторий не коммитятся, ожидаемые значения берутся с табло платформы:

```sh
CS2STATS_TEST_DEMO=path/to/match.dem CS2STATS_TEST_ROUNDS=22 CS2STATS_TEST_SCORE=13:9 \
  go test -run TestParseRealDemo -v ./internal/parser/
```

### Настройки (переменные окружения)

| Переменная      | По умолчанию          | Назначение                                        |
|-----------------|-----------------------|---------------------------------------------------|
| `DATA_DIR`      | `./data`              | каталог БД (`cs2stats.db`), демок (`demos/`) и временных файлов |
| `ADDR`          | `:8080`               | адрес HTTP-сервера                                |
| `MAX_DEMO_SIZE` | `1073741824` (1 ГБ)   | лимит размера демки после распаковки, байт        |
| `STATIC_DIR`    | `internal/webui/dist` | откуда раздавать фронтенд, если бинарь собран без тега `embedweb` |

### Структура

```
cmd/cs2stats      точка входа: сервер и CLI parse
internal/parser   демка → доменная модель матча (demoinfocs-golang)
internal/stats    расчёт метрик игроков
internal/ingest   приём файлов: распаковка, лимиты, sha256, хранилище демок
internal/worker   фоновая обработка очереди матчей
internal/store    SQLite: сессии, матчи, статистика
internal/api      HTTP JSON API
internal/webui    раздача собранного фронтенда
web/              React + TypeScript (Vite)
openspec/         спецификации и изменения (OpenSpec)
```

Все доработки ведутся через OpenSpec: `/opsx:propose` → `/opsx:apply` → `/opsx:archive`.

## Известные ограничения

- Rating считается по формуле HLTV 1.0: формулы 2.0/3.0 не опубликованы. В БД хранятся сырые счётчики, поэтому формулу можно сменить без повторного парсинга.
- ADR игрока, подключившегося посреди матча, делится на все раунды матча.
- В некоторых старых демках CS2 (бета 2023 года) нет событий урона. Для них ADR будет 0.
- Флеш-ассисты не засчитываются как ассисты.
